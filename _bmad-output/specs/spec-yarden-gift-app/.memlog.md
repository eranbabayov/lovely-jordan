- (capability) CAP-1 Entry gate: two fixed personal questions must be answered before any content is reachable.
- (capability) CAP-2 Endless photo slideshow auto-advancing in a loop over a photo set Eran supplies.
- (capability) CAP-3 Gift shelf showing each gift as a gift-box with live countdown to its reveal moment.
- (capability) CAP-4 Gift opening: box-opening animation then renders the gift content; opened gifts stay reopenable.
- (capability) CAP-5 Gift contents sealed at rest and unsealed with a key derived from the gate answers, so source inspection cannot spoil them.
- (capability) CAP-6 Author workflow: add photos or gifts later by dropping files and editing one config file, no component changes.
- (capability) CAP-7 Installable mobile app shell (PWA) so the gift opens fullscreen from her home screen.
- (capability) CAP-8 Optional ambient music started by the opening tap gesture, with an always-visible mute control.
- (decision) Gate protects the entire app, not only the gifts: the photos are personal too and anyone holding the URL would otherwise see them. Reason: privacy, and one ritual reads better than repeated ones.
- (decision) Unlock state persisted in localStorage so Yarden is not re-interrogated on every visit.
- (decision) Answer matching is deliberately forgiving (niqqud, bidi marks, spaces, punctuation, final-letter forms all normalized away) and has no attempt limit, with hints escalating after 3 and 6 tries. Reason: being locked out of your own gift is the worst possible failure.
- (decision) Answers stored as SHA-256 of the normalized form, never plaintext, so View Source does not reveal them.
- (decision) Gift payloads encrypted AES-256-GCM under PBKDF2-SHA256 of the normalized answers, so the Q and A performs real cryptographic work rather than a bypassable UI check.
- (decision) Time lock is soft for v1: reveal gating uses the server HTTP Date header to defeat casual device-clock changes, accepting that devtools can bypass it. Reason: threat model is an impatient girlfriend, not an attacker.
- (decision) Deferred: true cryptographic time lock via scheduled key publication (GitHub Actions cron committing the key at reveal time). Available later for any gift where early opening would genuinely ruin a surprise.
- (decision) Slideshow pace defaults to 4000ms with 800ms crossfade and slow Ken-Burns, exposed as a single SLIDE_MS constant; 1000ms as Eran originally asked remains supported. Reason: 1s hard cuts read as a strobe and are harsh on a phone screen; one constant makes the comparison trivial.
- (decision) Photos ordered chronologically by EXIF capture date, giving the loop an our-story-so-far arc instead of a shuffle.
- (decision) Reveal times stored as ISO-8601 with explicit offset, wall-clock intent pinned to Asia/Jerusalem, so a device in any timezone counts down to the same instant.
- (decision) First gift ships already unlocked with no countdown, so the app gives her something immediately before she discovers the locked ones.
- (decision) Stack: Vite + React + TypeScript + Tailwind, output a static dist/ directory. Reason: the gate-countdown-unlock flow is genuinely stateful, and the build still yields plain static files for free hosting.
- (constraint) No backend, no database, no server-side code: deployable as static files to a free tier. Rules out server-enforced locks and any runtime secret.
- (constraint) Must be served over HTTPS: crypto.subtle only exists in a secure context, so plain http from a bare IP silently breaks the gate and gift decryption.
- (constraint) Every secret ships to the client. No lock in this app is enforceable against a determined inspector; protections only raise effort.
- (constraint) Hebrew only, dir=rtl, document language Hebrew. Rules out any layout or copy that assumes LTR.
- (constraint) Mobile-first with iOS Safari as the reference browser: use 100dvh not 100vh, and respect safe-area insets.
- (constraint) Static hosts expose no directory listing, so the photo set must be enumerated by a build-time generated manifest.
- (constraint) Browsers cannot render HEIC, the native iPhone photo format, so the build must convert it. EXIF orientation must be baked in or portraits display sideways.
- (constraint) Plaintext gift sources must never be committed to version control; only sealed ciphertext is tracked. Rules out keeping gift content in the repo tree unignored.
- (constraint) Honor prefers-reduced-motion by replacing Ken-Burns and confetti with plain fades.
- (constraint) Single-maintainer editability: adding a gift must not require touching component code.
- (assumption) Photo count and total payload size unknown; pipeline sized for a few hundred phone photos with resize to 1600px and WebP q80.
- (assumption) Yarden opens the app on a modern mobile browser supporting WebP, crypto.subtle and CSS 3D transforms.
